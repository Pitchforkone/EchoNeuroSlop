# План прототипирования

## Фазы разработки

Прототип разбит на 4 последовательные фазы. Каждая фаза завершается **играбельным билдом**.

Задачи разделены:
- 💻 **Код** — реализует Copilot (C#, шейдеры, конфиги)
- 🎛️ **Инспектор** — настраивает разработчик вручную в Unity Editor
- 🔀 **Совместно** — Copilot пишет код, разработчик подключает в инспекторе

---

## Фаза 1: Чёрный мир + FPS-контроллер

**Цель:** игрок ходит в полной темноте, базовая инфраструктура готова.

### 💻 Код (Copilot)

- [x] **1.1** Реализовать `FPSController.cs` — CharacterController, обзор мышью, WASD-ходьба, бег (Shift)
- [x] **1.2** Настроить Input Actions в `InputSystem_Actions.inputactions` — движение, обзор, эхолокация (ЛКМ), бег
  > Input Actions уже содержали все нужные actions (Move, Look, Sprint, Crouch, Attack/ЛКМ). Изменения не потребовались.

### 🎛️ Инспектор (разработчик)

- [x] **1.3** Настроить сцену: удалить Directional Light, Environment Lighting → Ambient Color = чёрный, Skybox = None/чёрный
- [x] **1.4** Построить тестовый уровень из примитивов (кубы, стены, пол, коридоры, комната)
- [x] **1.5** Создать Player GameObject: добавить CharacterController + Camera (child) + FPSController
- [x] **1.6** В URP Asset (Settings/PC_RPAsset): убедиться что Depth Texture = On

### Результат фазы
Чёрный экран. Игрок двигается по уровню, но ничего не видит. Управление работает.

## Фаза 2: Эхолокация — ядро

**Цель:** работающий эхо-пульс. Клик — и мир на мгновение становится видимым.

> Реализуем **Подход A (Point Light)** для быстрой проверки. Переход на Подход C (Post-Process) — отдельный этап.
> См. [Техническая архитектура](technical-architecture.md) для сравнения подходов.

### 💻 Код (Copilot)

- [x] **2.1** Реализовать `EchoManager.cs` — синглтон, массив эхо-источников (max 16), обновление радиусов, очистка истёкших, спавн/удаление Point Light
- [x] **2.2** Реализовать `EchoSource.cs` — компонент-источник, регистрация в менеджере
- [x] **2.3** Реализовать `PlayerEchoLocator.cs`:
  - Активное эхо по ЛКМ (большой радиус, ~20м, яркое)
  - Пассивное эхо от шагов (малый радиус, ~5м, слабое)
- [x] **2.4** Создать ScriptableObject `EchoPreset.cs` — конфигурация параметров эхо (скорость, радиус, цвет, интенсивность) для удобной настройки в инспекторе

### 🎛️ Инспектор (разработчик)

- [ ] **2.5** Добавить `PlayerEchoLocator` на Player, привязать Input Actions
- [ ] **2.6** Создать EchoPreset ассеты (ПКМ → Create): «ActivePing» (яркий, 20м), «Footstep» (слабый, 5м) — и назначить их в PlayerEchoLocator
- [ ] **2.7** Тюнинг параметров: скорость волны, яркость, время затухания — через EchoPreset ассеты

### Результат фазы
Клик ЛКМ → от игрока расходится свет, обрисовывающий стены и объекты. Шаги дают слабую подсветку рядом.

## Фаза 2.5 (опционально): Апгрейд до Post-Process

**Цель:** переход с Point Light на screen-space пост-процессинг для визуал-апгрейда.

> Выполняется только если подход A подтвердил геймплей и нужен лучший визуал.

### 💻 Код (Copilot)

- [ ] **2.5.1** Написать `EchoPostProcess.shader` — HLSL полноэкранный шейдер (depth reconstruction, ring, edge detection)
- [ ] **2.5.2** Реализовать `EchoRendererFeature.cs` + `EchoRenderPass` — URP Renderer Feature
- [ ] **2.5.3** Обновить `EchoManager` — вместо Point Light передаёт данные в шейдер через `Shader.SetGlobal*`

### 🎛️ Инспектор (разработчик)

- [ ] **2.5.4** Добавить EchoRendererFeature в URP Renderer (Settings/PC_Renderer → Add Renderer Feature)
- [ ] **2.5.5** Убедиться что Depth Texture и Normals Texture включены в URP Renderer

### Результат
Контурная визуализация вместо заливающего света. Расширяющееся кольцо обрисовывает рёбра геометрии.

### 🎛️ Инспектор (разработчик)

  - Капающая вода (AmbientEchoSource, голубой, слабый, цикл)

## Приоритеты

| Приоритет | Что | Почему |
|---|---|---|
| 🔴 P0 | Фаза 1 + 2 (контроллер + эхо) | Это и есть игра |
| 🟡 P1 | Фаза 2.5 (пост-процесс) | Визуал-апгрейд, если Point Light недостаточно |
| 🟡 P1 | Фаза 3 (звуковая экосистема) | Делает мир живым |
| 🟢 P2 | Фаза 4 (геймплей) | Полный цикл, но можно тестировать и без |

## Метрики успеха прототипа

1. ✅ Игрок чувствует **слепоту** в тишине
2. ✅ Эхо-пульс создаёт **читаемую визуализацию** геометрии
3. ✅ Возникает **дилемма** «шуметь чтобы видеть vs. быть тихим чтобы выжить»
4. ✅ Стабильные **60 FPS** с 8+ одновременными эхо-источниками
5. ✅ Уровень можно **пройти**, ориентируясь только по эхо
